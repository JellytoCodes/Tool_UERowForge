# 작업 목록

기준: 2026-10-10 / v0.2.2. 아래 TD 번호는 **저장소 내부 작업 ID**다. GitHub Issue 번호가 아니며 원격 Issue는 아직 생성하지 않았다.

우선순위는 기능 수를 늘리기보다 **등록/에셋/빌드 경계 정리 → 실제 UE 검증 → 협업·배포 안정화** 순서다. `v0.2.3 후보`는 작업 묶음 제안이지 출시 약속이 아니다.

## 현재 기준선

완료: 공용 프로젝트 관리, 경로 기본값 단순화, JSON/행 헤더 생성, Getter Subsystem 생성, 전체 C++ 미리보기, 생성물 보호/이관, Python 테스트.

실험: 외부 UE에서 `.uasset` 생성·갱신, 전체 성공 후 INI 등록.

미검증: 실제 Unreal UHT/C++/BP/런타임/패키징, Windows GUI/EXE, GitHub 원격 CI.

## TD-001 · 예정 경로 등록을 에셋 생성과 분리

**P0 / v0.2.3 후보 / 미구현 / 다음 개발 1순위**

문제: 현재 `build_registration_plan()`은 이미 변환된 에셋 작업을 전제로 하고 `commit_registration()`은 `.uasset` 존재를 검사한다. 일반 변환은 INI를 쓰지 않는다. 개발자가 수동 생성한 에셋의 자동 연결 목표가 막힌다.

변경 방향: 코드·JSON과 같은 확정 변환 계획에 예정 경로 등록을 포함한다. 원본 JSON의 위치와 UE 오브젝트 경로는 별도로 유지한다. 등록과 `asset ready` 상태를 분리한다. 초기 동작은 사용자가 계획에서 INI 변경을 확인한 뒤 적용하게 한다.

주요 파일: `core.py`, `runtime_registration.py`, `unreal_runner.py`, `subsystem_codegen.py`, `gui.py`, 관련 테스트.

완료 조건:
- [ ] 신규 테이블의 `.uasset` 없이 JSON/C++/INI/manifest를 안전하게 생성한다.
- [ ] INI의 일반 경로는 `/Game/.../DT_Name.DT_Name`으로 기록한다.
- [ ] 기존 프로젝트의 미선택 테이블/수기 설정/인코딩/줄바꿈을 보존한다.
- [ ] 기존 런타임 등록 상태를 이관하며 외부 변경 시 중단한다.
- [ ] 값만 변경하면 C++/등록 구역의 내용이 같을 때 다시 쓰지 않는다.
- [ ] 로그/UI는 `예정 등록`과 `에셋 확인`을 구분한다. 가짜 성공 표시를 하지 않는다.
- [ ] 누락/틀린 행 타입에서 크래시 대신 null+진단을 유지한다.
- [ ] 같은 경로에 수동 생성한 정상 DataTable이 다음 게임 시작 때 로드되는 것을 실제 UE로 검증한다.
- [ ] 실패 복구 및 v0.2.2 이관 테스트를 작성하고 revision 변경 필요성을 검토한다.

## TD-003 · 에셋 반영 전 컴파일 스키마 검증 강화

**P1 / 미구현**

현재 bridge는 구조체 존재, 컬럼명 집합, 행 키 집합을 검사한다. **같은 이름의 필드 타입만 변경**된 상황에 최신 빌드 여부를 충분히 보장하지 못한다.

완료 조건:
- [ ] `Int → Float` 등 이름이 같은 타입 변경/필드 순서/기본값 정책의 검증 범위를 정한다.
- [ ] 요청 스키마와 컴파일된 FProperty 정보를 비교하는 UE 측 경로를 실제 지원 API로 검증한다.
- [ ] 소스 해시만으로 컴파일 최신 여부를 판정하지 않는다.
- [ ] 기존 에셋에 쓰기 전에 불일치를 발견하고 빌드 필요를 알린다.
- [ ] 에셋의 Source File/재임포트 메타데이터를 처리하는 범위도 명시하고 일반 Reimport 메뉴 동작을 검증한다.

## TD-005 · Git 협업용 설정과 생성물 이식성

**P1 / 미구현**

현재 프로젝트 목록·접두사·경로 설정은 PC 로컬 Registry에 있다. 생성 manifest는 프로젝트 상대 경로를 주로 쓰지만 이식 가능한 공용 설정 파일을 대신하지 않는다.

완료 조건:
- [ ] 로컬 프로젝트 루트/엔진 경로와 팀 공용 모듈/접두사/상대 경로 설정을 구분한다.
- [ ] 개발자 PC가 다른 루트에 clone해도 동일한 생성 결과를 얻는다.
- [ ] manifest를 함께 관리하며 OS/Git 줄바꿈 변환으로 불필요한 외부 수정 오류가 발생하지 않도록 정책을 정한다.
- [ ] 원본 엑셀 상대 경로 및 외부 엑셀 참조 방식, 사용자 경로 override 우선순위를 명시한다.
- [ ] 실사용 설정/개인 경로/자격증명이 도구 저장소에 들어가지 않게 한다.

## TD-008 · 삭제·이름 변경·경로 이동

**P2 / 보류**

선택 제외는 삭제가 아니다. 테이블/행 키/필드/에셋 이름 변경은 별도의 명시적 작업으로 처리한다. 이전 파일·참조·등록 경로와 복구 계획을 보여준 뒤 실행하는 설계가 필요하다. 소스 디렉터리 파일 이동과 UE 에셋 이동을 같은 파일 시스템 조작으로 처리하지 않는다.

## GitHub로 옮기는 방법

Issue 제목은 `[TD-001] 예정 경로 등록을 에셋 생성과 분리`처럼 작성하고 위 목적·완료 조건을 본문에 옮긴다. 브랜치 예시는 `feat/td-001-planned-registration`이다. GitHub Issue 번호가 생성되면 이 문서에 링크를 추가하되 TD-ID는 유지한다.

첫 PR은 문서/관리 기준선이며 기능 변경이 아니다. TD-001 구현은 별도 PR로 분리한다.
